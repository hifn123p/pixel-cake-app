PixelCake UI 改版预览

这是按 docs/UI_DESIGN.md 与 ui/theme/ 真实 token 复刻的静态预览，用于在无法本地构建的情况下肉眼验收版式、层次与密度。颜色 / 间距 / 圆角 / 字号全部取自代码里的 token 真值。

首页按反馈二次修订为极简：整屏只有一个展示位——它本身就是唯一入口（顶栏那个重复的「＋」已在 2026-09-22 删除）；设备规格表、工程信息已全部删除（「首页介绍不对」）。见屏 ①与⑤。

UI-4b 趋势对齐已落地（UI_DESIGN.md §1.6.1）：弹簧按属性分族、深色强调色降饱和、玻璃收敛为浮层专用（卡片默认实心容器）。本页 mockup 因此全部改用实心容器底 + 深色档强调色。

后续补做已落地（UI_DESIGN.md §1.6.2）：① 预设卡片改为真实缩略图（屏⑥）；② 新增 LocalDarkTheme 修掉「强制深色主题下取错色板」的真 bug；③ 半径滑块纳入渲染监听。

v0.3.0 真机反馈第三轮已落地（UI_DESIGN.md §4.0.3）：① 顶栏 56 → 44dp（= Spacing.controlHeight，导出胶囊 40 → 36dp 齐平）；② 预览 : 参数权重默认 0.62 → 0.45、SPLIT_MIN 0.28 → 0.22，且 GroupLabel 从 labelMedium+onSurfaceVariant 改 titleMedium+onSurface（此前与滑块右侧数值完全同款，面板层级等于不存在）；③ 预览框圆角从容器级 shell(40dp) 收到内容级 chip(14dp)。
本页 mockup 已同步：顶栏 44px、预览圆角 --r-chip、Radius 表 14 / 22 / 28 / 40。

调色范围扩展批次 1+2 已落地（TONING_DESIGN.md §10 · 代码未提交）：可调项 10 → 64；一级分类仍是 5 个，但 LUT 换成 颜色（LUT 降为它的二级）——本页三处分段条已同步改名。面板新增二级分组 chip 行（调色 → 影调 / 白平衡 / 偏好；颜色 → 混色 / 分级 / LUT；曲线 → 亮度 / 红 / 绿 / 蓝），它钉在滚动之外；混色 / 分级的分组内选择用带色块的 chip。
屏 ⑤ / ⑥ 的分段条已同步；新增的二级 chip 行尚未补 mockup，以 TONING_DESIGN.md §10 为准。

调色范围扩展批次 3 已落地（TONING_DESIGN.md §11 · 代码未提交）：可调项 64 → 71，新增一级分类 效果（5 → 6 个，排在曲线之后、预设之前 —— 预设留在最右端当肌肉记忆锚点）。二级为 暗角（强度 / 起点 / 过渡 / 圆度）与 颗粒（强度 / 尺寸 / 对比）。
本页三处分段条与「导航」表已同步为六段；效果的面板未补 mockup（它是一组普通滑块，形态与屏 ② / ③ 一致）。⚠️ 这一批是本项目第一次需要像素坐标的参数 —— 暗角与颗粒的几何一律走长边归一化坐标，否则「预览所见 = 导出所得」会断。6 个一级分类曾被认为触到硬上限（2026-09-23 已更正：上限其实是 7，见下段）。

调色范围扩展批次 4 已落地（TONING_DESIGN.md §12 · 代码未提交）：可调项 71 → 81，新增一级分类 细节（6 → 7 个，排在曲线之后、效果之前 —— 细节改的是画面的结构与质感，效果是往这个结构上再加一层）。二级为 锐化（4 项）、降噪（4 项）、质感（2 项）。
本页三处分段条与「导航」表已同步为七段。细节的面板未补 mockup（同样是普通滑块，形态与屏 ② / ③ 一致）。⚠️ 这一批与前三批性质不同：它是全项目唯一的邻域算子（输出依赖「一个像素周围长什么样」），所以只能承诺「预览与导出观感一致」，不能承诺逐位相同 —— 别拿逐位断言去卡它。它还必须排在人像精修之后（锐化晚于磨皮，否则磨皮会把刚锐出来的边缘糊掉，表现为「锐化滑块只有一半量程」）。一级上限由 6 更正为 7（`312/7 = 44.6dp` 够、`312/8 = 39dp` 不够）⇒ 加到第 8 个才必须让工具条横向可滚。

对象作用域调色（批次 5）已落地（OBJECT_TONE_DESIGN.md · 代码未提交）：可调项仍是 81 项 —— 这一批不新增参数，而是把同一套参数扩展成作用域化：整图 + 8 个识别对象（人物 / 皮肤 / 面部 / 身体 / 头发 / 衣服 / 配饰 / 背景）各一层、层可叠加。本页新增屏 ②b。
① 作用域行钉在二级 chip 行之上、也在滚动之外 —— 它决定「下面这些滑杆改的是谁」，滚出去就会变成「照片被改坏了但没人知道是哪一步干的」；② 细节 / 效果 下这一行仍在，但面板整体换成空态（暗角是画面几何、锐化是邻域算子，都只作用于整图）；人像 / 预设 不渲染这一行；③ 选中非「整图」时面板顶部出现层头部（作用域名 + 移除 + 层强度），而滑杆一字不改（分组标题 / 量程 / 重置 / Hint 全部自动跟随 ⇒ 批次 1~4 的 81 项面板零改动）；④ 层是叠加量：整图 +0.5EV 之上再叠人物 +1EV ⇒ 人物比「只开整图」再亮一档（不是回到 +1EV）。数据基础早已在包里：MediaPipe 六类分割模型此前只用了「皮肤」一路，另外 4 类算完即弃 ⇒ 本批推理成本零增长。

§2.4 可量化验收清单 · 逐条自查

这一项是本次改版的核心：把「好看」拆成能打钩的条目，避免靠感觉评审
  • ✔间距只用 4/8/12/16/24/32/48 · Spacing.kt 强制
  • ✔字号 ≤ 5 级（24/16/14/12/11） · bodySmall 别名到 11sp
  • ✔字重 ≤ 3 档（Normal / Medium / —）
  • ✔1 主色（浅 / 深两档）+ 6 灰阶 + 3 语义色
  • ✔深色强调色降饱和 ≈13% · SeedOnDark，对比度 4.11:1 → 6.04:1，过 WCAG AA
  • ✔圆角只用 4 档 + 胶囊 · chip 强制 Radius.chip
  • ✔卡片无粗边框无投影，层次靠容器底差 + 1px 极淡描边
  • ✔玻璃只用于浮层，承载型容器走实心 · GlassCard 默认 CardMaterial.Container
  • ✔拖动参数时隐藏非参数 UI · 顶栏/分隔条/工具条统一只降 alpha（不收高度，否则预览会跳）；inertUnless 保证淡出即不可点
  • ✔动效按属性分族：空间 0.6 / 颜色 1.0 / 透明度 tween · Motion.kt
  • ✔不做实时 backdrop 模糊 · 静态模糊底图一次生成
  • ✔无障碍：系统关动画时位移 / 缩放 / 淡入淡出全部坍缩 · 弹簧自带；7 处 tween 补 durationFor（修 bug）
  • ✔预设卡片带真实缩略图 · PresetThumbRow，按原图渲染，换图才重算（A 档）
  • ✔深色 / 玻璃色跟随生效主题而非系统 uiMode · LocalDarkTheme（修「编辑页在系统浅色下取到浅色板」的 bug）
  • ✔每个可点控件都有实际动作 · 可达性审计：无死按钮 / 无空壳开关
  • ◐点击次数 ≤ Snapseed · 待真机比对（编辑入口已减 1 跳）
  • ◐一加15 帧率实测 · UI-5 剩余项（承载面板已是实心，掉帧则进一步收玻璃浮层）
  • ◐CameraPanel 尚未迁移到新 token · 旧圆角/旧间距残留，排在后续
  • ◐EditorUiState 状态收敛 · 属「能力」不属 UI，单独立阶段

对应代码：ui/theme/*（token · 玻璃 + 实心容器 + LocalDarkTheme）、ui/components/*（GlassCard / GlassSegmentedBar / GlassChipRow / PresetThumbRow / ParamSlider / ActionTile）、ui/shell/AppShell.kt、ui/home/HomeScreen.kt、ui/settings/*、ui/editor/*（EditorScreen / EditorToolbar / ParamPanel / ExportSheet）、MainActivity.kt（含 buildPresetThumbs）。

本页为静态预览，用于版式与密度评审；真实动效与手势需在真机上核对。core/edit/**、core/camera/**、ml/** 在 UI 改版期间未改动（2026-09-23 注：其后「调色能力」批次 1+2+3+4 已改动 core/edit/** —— 批次 1+2 影调 / 白平衡 / 偏好 / HSL / 分级 / 曲线；批次 3 新增暗角 / 颗粒并让像素程序接收归一化坐标；批次 4 新增细节（锐化 / 降噪 / 质感）—— 它是邻域算子，被实现成「在目标位图上再跑一遍」的独立 pass，因此 PixelProgram 的签名在批次 4 没有再动；core/camera/**、ml/** 仍未动）。
